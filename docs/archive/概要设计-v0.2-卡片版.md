# AI 放映厅 · 产品概要设计 v0.2（四模块版）

> **一句话**：一个纯静态、可自托管的 **AI 学习站**——把这四个东西装进去：**AI 是怎么走到今天的**（发展史）、**它到底怎么工作的**（底层原理）、**面试被问到怎么答**（题库）、**5 分钟能做出什么**（实操）。每个模块都能「像刷短视频一样」一条接一条地过，不跑题。

> v0.1 是「B 站视频收藏站」；v0.2 的实质变化：**视频从「产品本体」降级为「一种素材」**。
> 面试题是卡片、实操是步骤，它们不该被塞进播放器里。所以架构从「视频为中心」改成「**模块 + 内容单元**」。

---

## 0. 先明确一个判断

你说的四个模块，其实是四种**完全不同的内容形态**：

| 模块 | 内容单元 | 用户的动作 | 核心页面该长什么样 |
|---|---|---|---|
| ① AI 发展史 | **事件**（某年某公司发布了什么） | 顺着时间线看 | 时间轴 + 事件卡 |
| ② 底层原理 | **概念**（RAG / Agent / Attention） | 看懂、建立关联 | 概念卡 + 前置关系 |
| ③ 面试题库 | **题目**（问题 + 怎么答） | 自我检测、背框架 | 题卡 + 翻面看答案 |
| ④ 实操工坊 | **项目**（10 分钟做一个东西） | 跟着做 | 步骤播放器 + 可复制提示词 |

如果硬把它们都做成「视频列表」，②③④ 会很难用：面试题你得反复翻，实操你得对着步骤一步步跟。
**结论：四个模块共用一个骨架（列表 → 详情 → 连续流），但各有自己的内容模型和专属视图。**

---

## 1. 目标与边界

### 1.1 产品定位

**不是视频网站，是「AI 知识自习室」。**

一个自用 + 可分享的静态站点，解决四件事：

1. **看懂来路**：AI 七十年的关键事件，按时间线串起来。
2. **看懂原理**：LLM / Agent / RAG 这些词到底指什么，彼此什么关系。
3. **敢去面试**：高频题 + 回答框架 + 追问陷阱。
4. **动手做**：照着步骤，10 分钟做出一个能跑的东西。

### 1.2 非目标

- 不做账号系统、不做社区、不做评论、不做 UGC。
- 不做实时资讯流（资讯可以作为一个**后续模块**，不放进 MVP）。
- 不做全站搜索 B 站（只搜本地策展数据）。

### 1.3 成功标准

1. 从打开到进入任意模块的任意一条内容，**≤ 2 次点击**。
2. 任意模块下连续刷 **20 条不跑题**。
3. **加一条内容 = 改一个 JSON**；加一个模块 = 加一个目录 + 注册一行。
4. 换设备不丢进度：收藏、掌握度、看到哪一步，都能导出导入。

## 3. 四个模块逐个设计

### 3.1 模块 ①：AI 发展史

**目标**：建立时间感——谁在什么时候做了什么，前后因果。

| 项 | 内容 |
|---|---|
| 内容单元 | **Event**：一个「发生过的节点」 |
| 列表视图 | **竖向时间轴**，左侧年份刻度，右侧事件卡，可拖动定位 |
| 双视角 | 时间视角（全部）/ 公司视角（只看一家公司） |
| 详情 | 一句话结论 + 前后因果 + 当时的技术条件 + 相关视频/论文 |
| 连续流 | 「沿时间线连播」：按年份顺序自动播下一条 |
| 关键交互 | 拖动年份轴快速跳；点公司 chip 切换视角；事件与概念互相跳转 |

**数据模型**

```jsonc
{
  "id": "chatgpt-2022",
  "year": 2022,
  "date": "2022-11-30",
  "org": "OpenAI",
  "title": "ChatGPT 发布",
  "summary": "第一次让普通人摸到大模型，2 个月 1 亿用户。",
  "why": "RLHF 把「会续写」变成「会对话」，是产品化而非技术跃迁。",
  "milestone": true,
  "concepts": ["rlhf", "llm"],
  "videos": [{ "bvid": "BV...", "title": "ChatGPT 到底做了什么" }],
  "articles": [{ "title": "...", "url": "..." }]
}
```

**界面要点**：时间轴不用第三方库，用 CSS + `IntersectionObserver` 做吸顶年份，性能好且可控。

### 3.2 模块 ②：底层原理

**目标**：把散落的名词连成一张网——你不仅知道 RAG 是什么，还知道它依赖 Embedding、和 Agent 什么关系。

| 项 | 内容 |
|---|---|
| 内容单元 | **Concept**：一个概念 |
| 列表视图 | **概念卡流**：一张卡 = 一句话 + 一张简图 + 前置概念 |
| 详情 | 一句话定义 → 为什么需要它 → 简图 → 3 分钟讲解视频 → 常见误解 → 面试关联 |
| 关联 | `prereq[]` 前置、`next[]` 后继，形成 DAG（顶部「学习路径」按拓扑排序生成） |
| 连续流 | 左右滑切概念；底部「懂了 / 再讲一遍」影响后续推荐 |
| 关键交互 | 点前置概念直接跳；概念 ↔ 面试题的交叉链接 |

**数据模型**

```jsonc
{
  "id": "rag",
  "title": "RAG（检索增强生成）",
  "oneLiner": "先把相关资料查出来，塞进提示词，再让模型回答。",
  "level": 2,
  "prereq": ["embedding", "vector-search"],
  "next": ["agent", "context-engineering"],
  "diagram": "rag.svg",
  "sections": [
    { "h": "为什么需要", "p": "模型知识有截止时间，且会编。" },
    { "h": "怎么工作", "p": "Query → 向量化 → 检索 Top-K → 重排 → 拼进上下文 → 生成。" }
  ],
  "misconceptions": ["RAG 不能解决所有幻觉", "不是向量库越大越好"],
  "videos": [{ "bvid": "BV...", "t": 0, "title": "RAG 全流程拆解" }],
  "interviewRefs": ["q-rag-01", "q-rag-02"]
}
```

**建议的首批 12 个概念**（形成一条路径）：
`Tokenization → Embedding → Attention → Transformer → Pretraining → SFT → RLHF/DPO → KV Cache → 推理模型（CoT） → RAG → Function Calling → Agent（ReAct）`

### 3.3 模块 ③：面试题库（四个模块里最容易被低估的）

**目标**：不是「看答案」，而是**练到能开口说**。所以它必须有两个模式：**浏览** 和 **自测**。

| 项 | 内容 |
|---|---|
| 内容单元 | **Question**：一道题 |
| 列表视图 | 题卡列表：题目 + 方向标签 + 难度 + 频次 + 掌握度圆点 |
| 详情结构 | ① 题目 ② 考察点（面试官在听什么）③ **回答框架（3-5 步骨架）** ④ 参考答案（口语化）⑤ 追问与陷阱 ⑥ 关联题 |
| 自测模式 | 随机/按方向抽题 → 计时思考 → 点「翻面」看框架 → 自评（会 / 模糊 / 不会）→ 进入下一题 |
| 复习机制 | 「模糊」「不会」进错题本；间隔重复（1 天 / 3 天 / 7 天） |
| 连续流 | 「面试官模式」连刷 10 题，中间不跳页 |
| 关键交互 | 框架默认折叠、答案默认隐藏（避免「看一眼就会」的错觉）；一键复制答案 |

**数据模型**

```jsonc
{
  "id": "q-rag-01",
  "question": "线上 RAG 召回率很低，你会怎么排查？",
  "topic": "rag",
  "level": 3,
  "freq": "高",
  "companies": ["字节", "阿里", "腾讯"],
  "考察点": ["有没有线上排查思路", "是否理解链路"],
  "outline": [
    "先分层：Query 改写 / 召回 / 重排 / 生成，逐层定位",
    "看指标：Recall@K、命中率、Top1 相关度",
    "常见原因：文档切分过碎、Embedding 与业务域不匹配、Query 与文档表述不一致",
    "给方案：Hybrid 检索 + Rerank + Query 改写，并给出验证方式"
  ],
  "answer": "我一般不会一上来就说换模型……（口语化 200 字）",
  "followUps": ["如果换 Embedding 模型，怎么评估收益？"],
  "related": ["q-rag-02", "q-embedding-03"]
}
```

**界面要点**：**答案默认隐藏**是这个模块的灵魂。一进来就看见答案，等于没练。

### 3.4 模块 ④：实操工坊

**目标**：看完就能做出来。核心是「**步骤**」——一条视频 10 分钟，你不可能记住他点哪了。

| 项 | 内容 |
|---|---|
| 内容单元 | **Walkthrough**：一个 5-10 分钟能完成的项目 |
| 列表视图 | 项目卡：封面 + 时长 + 工具链 + 难度 + 步骤数 |
| 详情 | 上方视频（小窗，可折叠）+ 下方**分步骤**：每步 = 标题 / 时长 / 你要做的操作 / **可复制的提示词或命令** / 预期结果截图 / 常见坑 |
| 联动 | 点步骤 → 视频跳到对应时间点；视频播到某秒 → 对应步骤高亮 |
| 边看边做模式 | 全屏步骤 + 大字提示词 + 一键复制 + 下一步 |
| 连续流 | 做完一个 → 推荐同工具链的下一个项目 |

**数据模型**

```jsonc
{
  "id": "w-pomodoro",
  "title": "10 分钟用 Cursor 做一个番茄钟",
  "duration": 600,
  "level": 1,
  "tools": ["Cursor", "Vite", "React"],
  "repo": "https://github.com/...",
  "video": { "bvid": "BV...", "cover": "..." },
  "steps": [
    {
      "t": 0, "dur": 60, "title": "建项目",
      "action": "打开 Cursor，新建空目录",
      "prompt": "用 Vite 初始化一个 React + TS 项目，只保留 App.tsx",
      "result": "step-1.png",
      "pitfall": "别装 Tailwind，这一步不需要"
    }
  ]
}
```

**界面要点**：提示词/命令必须是**可点一下复制**的块，而不是视频里的口头描述——这是这个模块存在的意义。

## 4. 统一的骨架（四个模块共用的部分）

这四块**只写一次**，所有模块复用：

| 能力 | 说明 |
|---|---|
| **列表页骨架** | 顶部：标题 + 筛选 chips；中部：卡片流；右侧：模块内搜索 |
| **详情页骨架** | 顶部返回 + 标题；主体按模块自定义；底部：收藏 / 下一个 / 进度 |
| **连续流（刷）** | 四个模块都有：上下/左右切换、预加载下一个、进度记忆、队列冻结 |
| **收藏 / 稍后看 / 进度** | 存在 localStorage，带 `moduleId` 区分 |
| **全局搜索** | 跨模块搜：事件 / 概念 / 题目 / 项目，结果按模块分组 |
| **深链接** | `/#/interview/q-rag-01`、`/#/concepts/rag`、`/#/build/w-pomodoro#step-3` |
| **导出备份** | 一份 JSON，含所有进度与收藏 |

### 4.1 「刷」的统一定义

`Flow` 组件接受任意 `items[]` 和一个 `renderItem`，负责：

- 一次只渲染 1 屏（当前）+ 预加载 1 屏；
- 支持纵向（手机）与横向（桌面）两种手势；
- 记录 `cursor`，刷新后回到原位置；
- 末尾不循环，而是弹出「本模块看完了 → 去下一个模块」。

**四个模块的 Flow 只是 `renderItem` 不同**：视频、概念卡、题卡、步骤。

## 5. 技术方案

### 5.1 选型

| 层 | 选择 | 理由 |
|---|---|---|
| 构建 | Vite | 纯静态产物，秒级构建 |
| 框架 | React + TS | 组件化，模块可插拔 |
| 样式 | Tailwind + CSS 变量 | 四模块换主题色只改变量 |
| 路由 | HashRouter | GitHub Pages 无 rewrite |
| 数据 | 仓库内 JSON + zod | 无后端，CI 校验 |
| 状态 | zustand + localStorage | 进度/收藏跨会话 |
| 部署 | GitHub Actions → Pages | 免费 HTTPS |

### 5.2 目录结构（模块化）

```
src/
├── app/                      # 路由、布局、TabBar
├── core/
│   ├── Unit.ts               # 统一内容单元的最小接口
│   ├── Flow.tsx              # 通用「刷」容器
│   ├── store.ts              # 进度/收藏/自评
│   └── search.ts             # 全模块搜索索引
├── modules/
│   ├── history/              # ① 发展史
│   │   ├── index.ts          # 导出一个 Module 对象
│   │   ├── schema.ts
│   │   ├── List.tsx  Timeline.tsx  Detail.tsx
│   ├── concepts/             # ② 原理
│   ├── interview/            # ③ 面试
│   └── build/                # ④ 实操
└── content/
    ├── history/events.json
    ├── concepts/concepts.json
    ├── interview/questions.json
    └── build/walkthroughs.json
```

### 5.3 模块接口（这是「能不断加模块」的关键）

```ts
export interface Module<T extends Unit> {
  id: string;                 // 'interview'
  title: string;
  icon: string;
  color: [string, string];
  list: React.FC<{ items: T[] }>;
  detail: React.FC<{ item: T }>;
  flowItem: React.FC<{ item: T }>;   // 「刷」的时候渲染啥
  schema: ZodSchema<T>;
  toSearchText: (item: T) => string;
}

export const modules = { history, concepts, interview, build };
```

新增模块 = 新建一个目录实现这 7 个字段 + 在 `modules` 里加一行 + 加一个内容 JSON。**首页、搜索、我的、Flow 全部自动生效，不需要改。**

### 5.4 B 站视频仍然只是「素材」

- 事件/概念/项目详情页里，视频是一个**区块**，不是主角。
- `iframe` 跨域限制不变：读不到播放事件 → 计时连播 + 手动切换兜底。
- 实操模块的视频建议**自录**（手机/屏幕录制），因为需要和步骤时间点对齐；第三方视频对不上步骤。

## 6. 内容怎么生产（四个模块四条流水线）

| 模块 | 来源 | 生产方式 | 频率 |
|---|---|---|---|
| 发展史 | 公开资料 + B 站纪录片/回顾类视频 | 我先用大模型生成事件骨架 → 你补漏 → 每条配 1-2 个视频 | 一次建库，季度补 |
| 原理 | B 站优质讲解 + 经典博客 | 大模型生成概念卡初稿 → 你审核 → 配视频与图解 | 每周 2-3 个 |
| 面试 | 你的面试经历 + 公开面经 + 大模型生成框架 | **框架必须你认可**，参考答案可以 AI 起草你改写 | 每周 5 题 |
| 实操 | B 站「5 分钟做出 XX」类视频 | 拆步骤（这步最费人力，但一次拆完永久可用） | 每周 1 个 |

> 面试模块要特别注意：**参考答案必须写「怎么开口说」，不是「知识点罗列」**。
> 格式统一为：先定性 → 分点 → 举例 → 收尾，300 字以内。

## 7. 部署

1. 建仓库 → 推 `main`。
2. `vite.config.ts` 设 `base: '/<repo>/'`。
3. Settings → Pages → Source: GitHub Actions。
4. `.github/workflows/deploy.yml`：install → build → upload-pages-artifact → deploy-pages。
5. 访问 `https://<user>.github.io/<repo>/`。
6. CI 里跑 `zod` 校验：任何一条内容字段缺失 / 引用不存在，**构建直接失败**，坏数据上不了线。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 四个模块都想做好 → 摊子铺太大 | 一个都做不完 | **按模块分期上线**（见第 9 节），发展史 + 原理先上 |
| 面试题内容质量 | 答案平庸 = 没用 | 你亲自定框架，AI 只做初稿；每题的「考察点」必须写 |
| 实操步骤拆解成本高 | 更新慢 | 先做 5 个精品，不追求数量 |
| 视频失效 | 页面开天窗 | `status` 字段 + 自动跳过 + 去 B 站 |
| iframe 跨域 | 连播不精确 | 计时 + 手动，文案不承诺全自动 |
| 内容越加越乱 | 找不到 | 模块 → 方向 → 标签 → 搜索 四层；季度整理 |
| 版权 | 索引与跳转，不下载 | 页脚声明；实操视频建议自录 |

---

## 9. 里程碑（按模块分期，每期都能上线）

| 期 | 内容 | 估时 |
|---|---|---|
| **M0 骨架** | 路由 + TabBar + 四个空模块 + Flow 容器 + 本地存储 | 1 天 |
| **M1 发展史** | 时间轴 + 公司视角 + 事件详情 + 20 条真实事件 | 1.5 天 |
| **M2 原理** | 概念卡流 + 前置关系 + 12 个概念 | 1.5 天 |
| **M3 面试** | 题库 + 题卡 + 自测模式 + 30 题 | 1.5 天 |
| **M4 实操** | 步骤播放器 + 复制提示词 + 5 个项目 | 1.5 天 |
| **M5 打磨** | 搜索、我的、导出、移动端手势、部署 | 1 天 |

**建议顺序：M0 → M1 → M2 → 上线 → M3 → M4。** 先有两个模块可看，再补后两个。

---

## 10. 需要你确认的 4 件事

1. **模块顺序**：先做「发展史 + 原理」，还是先做「面试 + 实操」？（后者更实用，前者更完整）
2. **面试题的答案标准**：你面试的是**大模型应用 / Agent 岗**，还是**算法岗**？两者的题完全不同。
3. **实操素材**：用 B 站别人的视频来拆步骤（快，但步骤可能对不上），还是你自己录（慢，但完全对齐）？
4. **是否要「学习路径」**：把四个模块串成一条线（先看发展史 → 再学原理 → 再刷题 → 再做项目）。
