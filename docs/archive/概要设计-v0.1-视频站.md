# AI 放映厅 · 产品概要设计（v0.1 草案）

> 一句话：**一个纯静态、可自托管、可无限扩展的「AI 主题视频策展站」**——把你在 B 站刷到的 AI 好视频分门别类收好，打开就能按主题一条接一条地看，像刷短视频一样停不下来。

- 形态：静态网页，部署在 GitHub Pages，通过链接直接访问；无后端、无登录、无数据库。
- 内容：B 站视频索引（iframe 内嵌播放 + 跳转原站），由你（+ 大模型辅助）策展入库。
- 核心体验：**选主题 → 一键连播 → 上滑换一条，但始终不跑题**。

---

## 1. 目标与边界

### 1.1 要解决的问题

| 现在的痛点 | 期望 |
|---|---|
| 好视频看完就忘，找不回来 | 建一个自己的「AI 视频图书馆」，永久可翻 |
| 每次看都要重新搜、被推荐流带走 | 打开即看，主题锁定，不被算法劫持 |
| 收藏夹一锅粥，没有分类和顺序 | 按主题 + 章节组织，有「学习路径」感 |
| 看完一条要想下一条看啥 | 队列自动连播，断了也能接着看 |

### 1.2 目标用户

主要是「你」（个人知识管理 + 娱乐），其次是可以把链接分享给同好朋友。**不做社区、不做 UGC、不做评论、不做实时全站搜索。**

### 1.3 成功标准（自用视角）

1. 从打开网页到视频开始播，**≤ 2 次点击**。
2. 任意主题下连续刷 **20 条视频不跑题**。
3. 新增一个主题 / 一批视频，**只改 JSON，不改代码**，10 分钟内上线。
4. 换设备 / 换浏览器，收藏和历史**可导出导入**，不丢。

## 2. 信息架构

```
AI 放映厅
├── ① 发现 /                    ← 首页，解决「不知道看啥」
│    ├── 继续观看（断点续看）
│    ├── 主题频道宫格（6 个，可扩展）
│    ├── 今日精选（人工置顶 1 条）
│    └── 最近更新
├── ② 频道 /topic/:id           ← 一个主题 = 一个频道
│    ├── 主题简介 + 章节导航 + 数据（条数/时长）
│    ├── 队列（可筛选：时长 / 难度 / 年份 / UP 主）
│    └── 主按钮：「开始连播」「随机一集」
├── ③ 播放 /watch?topic=xx&i=3  ← 沉浸式刷视频
│    ├── 上滑下一条 / 下滑上一条（队列内）
│    ├── 队列抽屉（看进度、跳集、重排）
│    └── 收藏 / 不感兴趣 / 分享 / 打开 B 站
├── ④ 搜索 /search
└── ⑤ 我的 /me
     ├── 收藏 · 观看历史 · 稍后看 · 不感兴趣
     ├── 我的主题（自建频道，V2）
     └── 数据备份（导出 / 导入 JSON）
```

| 5 | **行业资讯** | 谁发布了什么、谁融了多少钱 | 模型发布 / 产品动态 / 融资并购 / 政策 |

### 2.2 内容单元

| 单元 | 含义 | 归属 |
|---|---|---|
| **Topic（主题/频道）** | 一个可持续扩充的内容集合 | 顶层 |
| **Section（章节）** | 主题内的顺序分段，形成「学习路径」 | 属于 Topic |
| **Video（视频）** | 一条 B 站视频的索引 + 策展信息 | 属于 1..n 个 Topic |
| **Queue（队列）** | 播放顺序 = 某主题下筛选后的有序列表 | 运行时生成 |
| **Module（模块）** | 一种内容形态的呈现方式（视频/文章/播客/论文） | 全局注册 |

## 4. 关键交互设计

### 4.1 主流程

```
发现页 → 点主题卡 → 频道页 → 「开始连播」 → 沉浸播放页
                                              ↑        ↓
                                        上/下滑切集  队列耗尽 → 换主题 / 同主题推荐
```

### 4.2 沉浸播放页（最核心，决定成败）

- **布局**：顶部导航（返回 / 主题名 + 进度 `3/42` / 更多），中间 16:9 播放器，右侧竖排操作（收藏、不感兴趣、分享、去 B 站），下方标题与 UP 信息，底部进度与「上滑看下一个」提示。
- **切集手势**：移动端整页纵向 `scroll-snap`，一次一屏；桌面端 `↑/↓` 或滚轮。切换时**只保留当前 iframe，其余为封面占位**，避免同时加载多个播放器拖垮页面。
- **自动连播**：当前视频按元数据时长计时，到时自动切下一条（见 5.4 的技术折衷）；顶部始终有「自动连播 ON/OFF」开关。
- **不跑题**：队列在进入播放页时由「主题 + 筛选条件」生成并冻结；切集只在这个队列内循环，不会滑进推荐流。
- **不感兴趣**：写入 `disliked`，立即切下一条，之后不再出现在队列里。
- **断点**：每次切换记录 `{topicId, videoId, position}`，回到首页「继续观看」。

### 4.3 空状态与边界

| 场景 | 处理 |
|---|---|
| 视频被删 / 无法播放 | 显示「该视频可能已下架」+ 自动跳过 + 「打开 B 站试试」 |
| 队列只剩 1 条 | 隐藏上滑提示，显示「本主题看完了，去下一个主题？」 |
| 首次访问（无历史） | 首页不显示「继续观看」，用「今日精选」占位 |
| 数据加载失败 | 显示离线提示 + 重试按钮（静态站也要体面） |
| 竖屏短视频 | 卡片标注「竖屏」，播放器区域上下留黑 + 提示「建议在 B 站 App 观看」 |

## 5. 技术方案

### 5.1 选型

| 层 | 选择 | 理由 |
|---|---|---|
| 构建 | **Vite** | 产物是纯静态文件，秒级构建，GitHub Pages 零配置 |
| 框架 | **React + TypeScript** | 组件复用、生态成熟、适合后续扩展模块 |
| 样式 | **Tailwind CSS**（或原生 CSS 变量） | 快速迭代 + 设计 token 统一 |
| 路由 | **HashRouter** | GitHub Pages 项目页没有服务端 rewrite，`#` 路由最稳，不会 404 |
| 数据 | 仓库内 JSON + 构建期 zod 校验 | 无后端，内容即代码，PR 即发布 |
| 状态 | localStorage + 轻量 store（zustand） | 无需账号即可跨会话保存 |
| 部署 | GitHub Actions → Pages | 免费、HTTPS、可绑自定义域名 |

> 备选：不想要构建链的话，可以用单文件 HTML + 原生 JS，但内容一多就难维护，不建议。

### 5.4 B 站播放集成（关键约束，必须提前知道）

嵌入方式：

```html
<iframe
  src="https://player.bilibili.com/player.html?bvid=BV1xx411c7mD&page=1&autoplay=0&danmaku=1&high_quality=1&as_wide=1"
  allow="autoplay; fullscreen; picture-in-picture"
  referrerpolicy="no-referrer"
  scrolling="no" frameborder="0" allowfullscreen
/>
```

三个绕不开的限制与对策：

| 限制 | 说明 | 对策 |
|---|---|---|
| **跨域，拿不到播放事件** | iframe 里的 `ended / pause / currentTime` 我们一律读不到 | ① 用元数据 `duration` 计时，到时自动切集；② 必须给用户「暂停自动连播」开关；③ 提供「去 B 站看」兜底 |
| **自动播放会被浏览器拦** | 无用户手势时，带声音自动播放基本会被拦 | 进入播放页先显示封面 + 大播放按钮（这是一次用户手势），点击后才挂载 iframe；`autoplay=1` 仍可能被拦时，提示「点一下播放器里的播放键」 |
| **封面图片有防盗链** | B 站图床校验 referer | `<img referrerpolicy="no-referrer">`；或用 `@480w_270h_1c.webp` 后缀取缩略图；仍失败则回退到主题渐变色块 |

> 结论：**「像刷短视频一样」的流畅感，靠的是队列切换和界面转场，而不是去控制 B 站播放器。** 播放页的体验设计要把这一点做顺（切换时立刻显示下一条封面和标题，播放器随后加载）。

### 5.5 内容生产（用大模型帮你找视频）

```
① 采集：scripts/fetch-bilibili.mjs
   - 关键词搜索（"AI 发展史" "Transformer 原理" "Kimi 发布会" ...）
   - B 站搜索接口需要 WBI 签名 + 登录 Cookie，仅本地运行，Cookie 用环境变量，绝不入库
② 筛选：导出候选 CSV/JSON（标题、UP、播放量、时长、发布日期）
③ 打标：把候选丢给大模型，输出 topic / section / tags / level / 一句话推荐
④ 人工过一遍：删掉标题党、广告、重复，调整顺序
⑤ 写入 content/videos/*.json → commit → GitHub Action 自动构建发布
```

频率建议：每周一次，每次 10-30 条。**不追求海量，追求「每条都值得看」。** 采集失败不影响线上（数据是构建期固化的）。

### 5.6 性能

- 路由级代码分割，首屏 JS 目标 < 200KB（gzip）。
- 视频数据按主题分片，进入频道页才加载该主题的 JSON。
- 封面 `loading="lazy"` + 渐变色占位，滚动不闪。
- 播放页同一时刻只挂载 1 个 iframe，前后各预载 1 张封面。
- 构建产物带 hash 文件名，长缓存。

## 6. 可扩展性设计（重点）

你说了「未来还会加很多模块」，所以架构上要满足：**加内容不改代码，加主题不改代码，加形态只加一个目录。**

### 6.1 三层扩展模型

| 层级 | 你要做的事 | 工作量 | 是否需要改代码 |
|---|---|---|---|
| L1 加视频 | 往 `content/videos/xx.json` 加一条 | 2 分钟 | 否 |
| L2 加主题/频道 | 新建 `content/topics/xx.json` + 视频文件 | 10 分钟 | 否 |
| L3 加内容形态（文章/播客/论文） | 在 `src/modules/` 加一个模块并注册 | 半天 | 是，但只加不改 |
| L4 加播放源（YouTube/本地 MP4） | 在 `src/modules/player/` 加一个适配器 | 半天 | 是，但只加不改 |

### 6.2 模块注册表（L3）

```ts
// src/modules/index.ts
export interface ContentModule {
  kind: string;                            // 'video' | 'article' | 'podcast'
  card: React.FC<{ item: ContentItem }>;   // 列表里的卡片
  player: React.FC<{ item: ContentItem }>; // 播放页里的主体
  icon: string;
}

export const modules: Record<string, ContentModule> = {
  video: videoModule,
  // article: articleModule,   ← 未来只加这一行
};
```

`ContentItem` 只约束最小公共字段（`id / kind / title / source / url / tags`），各模块自带自己的扩展字段。**页面层永远面向 `ContentItem` 编程，所以新增形态不会动到首页、频道页、播放页。**

### 6.3 数据兼容

- 每个 JSON 带 `"schemaVersion": 1`；构建期用 zod 校验，**校验失败直接让 CI 红**，不会把坏数据发上线。
- 新字段一律可选，旧数据永远能读；需要破坏性变更时写迁移脚本，而不是手改所有文件。

### 6.4 预留但暂不实现

- 多语言（中/英字段）—— 先不做，但标题字段不做特殊处理，未来加 `title_en` 即可。
- 多人协作策展 —— 用 GitHub PR 就够了，不需要权限系统。
- 观看统计 —— 静态站无后端，最多做本地统计；要看真实数据就接第三方（如 Umami），默认不接。

## 7. 部署上手（GitHub Pages）

1. 建仓库 `ai-theater`（public），推到 `main`。
2. `vite.config.ts` 里设 `base: '/ai-theater/'`（用自定义域名则设 `'/'`）。
3. 仓库 Settings → Pages → Source 选 **GitHub Actions**。
4. 加 `.github/workflows/deploy.yml`：`pnpm install → pnpm build → upload-pages-artifact → deploy-pages`。
5. 每次 push 自动发布，地址形如 `https://<你的用户名>.github.io/ai-theater/`。
6. 项目页无服务端路由 → 用 HashRouter，URL 形如 `.../#/topic/ai-history`。
7. 想更快（国内访问）：同一份产物可同时部署到 Cloudflare Pages / Vercel，互不影响。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| B 站播放器自动播放被拦 / 无法监听结束 | 连播体验打折 | 计时连播 + 手动上滑 + 「去 B 站」兜底；文案上不承诺「全自动」 |
| B 站改版 / 接口风控 | 采集脚本失效 | 采集只在本地跑，线上数据是固化的；脚本单点可替换 |
| 视频下架 | 播放页空白 | `status` 字段 + 播放页失败提示 + 一键跳过 |
| 封面防盗链 | 列表图裂 | no-referrer + 渐变兜底 |
| 版权 | 只是索引与跳转，不下载不转码 | 页脚注明「内容版权归原作者，本站仅做策展索引」 |
| 内容越加越乱 | 找不回来 | 主题 + 章节 + 标签 + 搜索四层；每季度整理一次 |
| GitHub Pages 国内速度 | 首屏慢 | 静态资源体积控制 + 可选备用部署 |

## 9. 里程碑（估算）

| 阶段 | 内容 | 估时 |
|---|---|---|
| M1 | 脚手架 + 内容 schema + 首页/频道页静态渲染 | 0.5 天 |
| M2 | 播放页 + iframe 集成 + 队列切集 | 1 天 |
| M3 | 手势/快捷键 + 自动连播 + 进度记忆 | 1 天 |
| M4 | 收藏/历史/搜索/筛选 + 我的页 | 0.5 天 |
| M5 | 采集脚本 + 大模型打标 + GitHub Action | 1 天 |
| M6 | 视觉打磨 + 移动端适配 + 上线 | 0.5 天 |

**先做能用的，再做好看的。** 建议第一次上线就带 20-30 条真实视频，而不是 6 个空频道。

## 10. 需要你拍板的几件事

1. **名字**：暂定「AI 放映厅」，要不要换个更个人的？
2. **端**：手机优先（地铁上刷）还是桌面优先（大屏看长视频）？我默认手机优先、桌面居中大卡。
3. **首批内容**：先做哪 3 个主题？建议「AI 发展史 + 大模型原理 + 公司档案」。
4. **采集方式**：你愿意提供一次 B 站 Cookie 让我写采集脚本，还是先全手工录 20 条？
5. **是否要「每日一句/每日一视频」**：可以加，成本很低，看你想不想要。
