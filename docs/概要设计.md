# AI 放映厅 · 概要设计 v0.4（极简版）

> **一句话**：一个纯静态的 AI 视频站。**选一个模块 → 一直往下刷 → 喜欢 / 不感兴趣**。就这么简单。
>
> 交互不是难点，**选片才是**。所以这份文档很短，重点在最后一节和第 3 节。

---

## 0. 这一版砍了什么

v0.3 里那些东西，全砍了：

| 砍掉 | 为什么 |
|---|---|
| 时间轴 / 公司视角 | 你不需要按年份逛，你只需要一直刷 |
| 概念卡 / 前置关系 | 同上，概念就是一堆视频 |
| 章节时间点 | 刷的时候根本不会点，反而挡路 |
| 多级导航 / 搜索 | 4 个模块 + 1 个列表就够了 |
| 面试答题卡 / 步骤表 | 你要的是视频，不是表单 |

**留下的只有：4 个模块 × 3 种场景 + 一个刷的界面 + 一个列表 + 两个按钮。**

---

## 1. 三种场景，三个队列

这是整个产品唯一需要想清楚的事。

| 场景 | 什么时候 | 队列里放什么 | 播放行为 |
|---|---|---|---|
| **🎯 专注** | 坐下来认真看 | 长视频（**> 5 分钟**），需要看画面 | 播完**停住**，不自动跳 |
| **☕ 刷一刷** | 闲得没事，脑子放松 | 短视频（**≤ 5 分钟**） | 自动连播，上滑跳过 |
| **🎧 只听** | 骑车、吃饭、走路 | 标了「不靠画面也能懂」的视频，长短都行 | 盖住画面，只出声，屏幕常亮 |

关键点：**同一个视频可以同时属于多个场景**。

- 一个 31 分钟的 OpenAI 访谈 → `专注` + `只听`（口播型，不看画面也能懂）
- 一个 7 分钟的 Transformer 类比讲解 → `刷一刷` + `专注`（虽然短，但需要看图）
- 一个 10 分钟的 Cursor 实操 → 只有 `专注`（必须看屏幕）

所以「100 条视频」能撑起三个各 60-80 条的队列，不用真的准备 300 条。

## 2. 界面：5 个屏，没有多余的东西

```
① 首页          4 张模块卡（写清还剩多少条、三个场景各多少）
        ↓ 点一张
② 播放（刷）     一屏一条，上滑下一条，只有「喜欢 / 不感兴趣」
        ↕ 顶部三个字切换场景（专注 / 刷一刷 / 听）
③ 只听          封面 + 标题 + 进度，画面被盖住
        ↗ 右上角
④ 列表          想挑着看时用：按 UP 主分组，可筛短视频 / 长视频 / 未看
⑤ 我的          看了多少 / 喜欢多少 / 赞踩在调什么
```

没有底部 tabbar，没有搜索框，没有二级页面。返回 = 回首页。

### 2.1 刷的界面

```
┌──────────────────────────┐
│ ‹ AI 发展史  [专注|刷一刷|听]  3/87 │
│ ┌──────────────────────┐ │
│ │                      │ │
│ │      视频（占大半屏）  │ │
│ │                      │ │
│ └──────────────────────┘ │
│ Transformer 到底在干嘛…   │
│ 飞天闪客 · 48.2 万 · 7:24 │
│ [ 👍 喜欢 1.2万 ] [ 👎 不感兴趣 ] │
│ 原理 · 讲人话 · 7 分钟     │
│ ▬▬▬──────────────────── │
│      上滑下一个            │
└──────────────────────────┘
```

- 竖屏整页 `scroll-snap`，一次一屏。
- 只有当前这条挂载 iframe，上下是封面占位（否则一次加载 10 个播放器会卡死）。
- 喜欢 / 不感兴趣 → 立刻记下，进入下一条。
- **不做**：评论、弹幕开关、倍速、清晰度。这些 B 站自己都有。

### 2.2 只听

- iframe 仍然留在页面里（移出视口或 `display:none` 会被浏览器暂停），**上面盖一层「音频播放器」UI**。
- 用 `navigator.wakeLock` 保持屏幕常亮。
- 只放「不依赖画面」的视频：纯口播、访谈、复盘。代码演示、画图讲解不进这个队列。
- **诚实的限制**：锁屏 / 切后台时浏览器会暂停，做不到真后台播放。想真后台只能点「去 B 站」。

## 3. 不重复：靠这三件事

你说「上百条，不管怎么刷都不会重复」，这需要三个机制一起：

1. **已看集合**：看过就写进 `seen`，队列生成时排除；30 天后才允许重新出现（如果你想二刷）。
2. **随机起点**：每次进入模块，从队列里随机取一个位置开始，不总是从第 1 条。
3. **刷完就停**：队列到底 → 「这个模块看完了，换一个」。不循环、不重复播。

单个模块的量：**最终目标 100-150 条**（短视频 40-60、长视频 60-90）。

**首批先上 60 条**（四个模块 × 15 条），跑起来看手感，再按周补到 100+。

## 4. 数据模型

```jsonc
// data/videos.js（本质是 JSON，外面包一层 window.THEATER_DATA = ）
{
  "bvid": "BV1xx411c7mD",
  "title": "Transformer 到底在干嘛？用一个类比讲清楚",
  "up": "飞天闪客",
  "cover": "https://i0.hdslb.com/...",
  "duration": 444,              // 秒
  "module": "concepts",         // history | concepts | interview | build
  "modes": ["focus", "relax"],  // 这个视频适合哪些场景
  "tags": ["Transformer", "讲人话"],
  "quality": 88,                // 策展引擎打分
  "status": "ok"
}
```

**更新内容只需要改这一个文件**：加一条视频 = 往 `videos` 数组里加一个对象；换一个模块的文案 = 改 `modules`。页面（`index.html` / `app.js` / `style.css`）一个字都不用动。

```ts
// localStorage
{
  seen: string[],                  // bvid，30 天后过期
  liked: string[],
  disliked: string[],
  progress: Record<string, number>, // 看到第几秒（用于续播）
  prefs: { lastModule: string; lastMode: 'focus' | 'relax' | 'listen' }
}
```

> `modes` 是关键字段。它决定一个视频进哪几个队列——也决定了「只听」能不能成立。

## 5. 技术方案

| 层 | 选择 | 为什么 |
|---|---|---|
| 构建 | **无构建** | 三个文件，双击 `index.html` 就能跑 |
| 框架 | **原生 JS** | 页面就 5 个，不值得上框架 |
| 样式 | 原生 CSS + 变量 | 四模块只换主题色 |
| 路由 | hash（`#/m/concepts/relax`） | 刷新不丢、静态托管直接可用 |
| 数据 | **`data/videos.json`**（页面 `fetch` 读取） | 内容和页面彻底分离：改数据不碰代码 |
| 状态 | localStorage | 无后端、不上传 |
| 部署 | 推仓库 → Settings → Pages → main / root | 没有 CI，没有构建，推上去就是最新 |

**播放器**：B 站 iframe。

```
https://player.bilibili.com/player.html?bvid=BVxxx&autoplay=1&danmaku=0&high_quality=1
```

- 自动连播：用元数据 `duration` 计时，到时切下一条（读不到真实结束事件）。
- 续播：记录秒数，重建 iframe 时带 `&t=秒`（已验证该参数可用）。
- 切下一条时销毁旧 iframe，只保留当前一条。

## 7. 风险

| 风险 | 对策 |
|---|---|
| 自动播放被浏览器拦 | 首次点击后挂载 iframe；给「点一下播放」兜底 |
| 锁屏暂停（只听场景） | 屏幕常亮 + 明确提示；真要后台去 B 站 |
| 队列不够刷 | 每模块目标 100+；不够时首页提示「去跑一次采集」 |
| 刷到的还是烂视频 | 这是核心问题，见《策展引擎》——评分 + 人工终审 |
| 越刷越窄 | 赞踩只调抓取策略，不改变当前队列的多样性 |

## 8. 你说过的话，我记在这里

- 「不管怎么刷，都是这一类的视频」→ 队列锁模块。
- 「上百个，不会重复」→ 已看集合 + 随机起点 + 刷完即停。
- 「长视频 / 短视频分开」→ 专注 / 刷一刷。
- 「骑车、吃饭时听」→ 只听模式 + `listen` 标签。
- 「可以点喜欢不喜欢，方便以后调整抓取」→ 赞踩落到作者权重和标签权重。
- 「难点在挑优质视频」→ 所以《策展引擎》才是这个项目的主线。
