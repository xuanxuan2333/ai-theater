# 策展引擎设计（内容从哪来、怎么判优劣）

> 目标：**自动找到「飞天闪客 / 3Blue1Brown 那种视频」，并且越多越好**，让你打开网站就能一直往下刷，刷到的每一条都不冤。

核心结论先说：

1. **关键词搜索是最差的一路**——搜出来的头部都是标题党和合集。真正高质量的来源是「**以你喜欢的 UP 为种子，走 B 站的相关推荐图**」。
2. **播放量高 ≠ 好**。营销号播放量往往最高。要看的不是绝对值，而是**互动率、收藏率、评论区语义**。
3. **负信号一票否决**比正信号加权更重要。宁可少 30 条，不要混进 3 条念稿的。
4. 大模型不用来「找视频」，用来**读标题 + 简介 + 高赞评论，判断它是不是在讲人话**。

---

## 1. 四路来源，质量从高到低

| 优先级 | 来源 | 怎么拿 | 为什么 |
|---|---|---|---|
| ★★★★ | **种子扩散** | 拿你认可的 BV（飞天闪客、3B1B），调 `archive/related` 拿相关视频，再对结果递归一层 | B 站的相关推荐就是「同圈层」，比关键词准得多；能捞到小 UP 的宝藏视频 |
| ★★★ | **信任 UP 追更** | 维护一份 UP 名单（mid），每周查新投稿 | 你已经验证过他的水平，直接信 |
| ★★★ | **站外清单** | 知乎「学习大模型必看视频」、掘金、V2EX、GitHub awesome、Newsletter | 有人替你筛过一遍，命中率高；用大模型从长文里抽 BV 号 |
| ★★ | **关键词搜索** | `wbi/search/type`，每个主题 10-20 组 query | 覆盖新内容、补长尾；但头部噪声大，只取前 3 页且必须过评分 |
| ★ | **分区热门 / 每周必看** | `ranking/v2` | 用来发现「破圈」的科普视频，偶尔有惊喜 |

### 冷启动配方（第一周就能有 300 条）

```
20 个种子 UP × 每个 2 层相关推荐 ≈ 400 条
+ 30 组关键词 × 每词前 20 ≈ 600 条（去重后剩 ~300）
→ 合并去重 ≈ 500 条 → 打分后 ≥80 的约 150 条 → 人工过一遍留 100 条
```

**第一批 20 个种子 UP 建议**（你可以替换）：飞天闪客、3Blue1Brown、李沐、跟李沐学AI、硬核的Heixel、小 Lin 说、图灵的猫、机器之心、量子位、AICG 研究员…（先填你真正看过的，这比什么算法都准）

## 2. 采集：具体接口与坑

| 用途 | 接口 | 说明 |
|---|---|---|
| 搜索 | `x/web-interface/wbi/search/type` | **需要 WBI 签名 + buvid3**，每页 20 条 |
| 相关推荐 | `x/web-interface/archive/related?bvid=` | 返回 ~30 条，通常不需要登录——**最划算的一路** |
| 视频详情 | `x/web-interface/view?bvid=` | 拿 `stat`：播放、点赞、投币、收藏、分享、评论、弹幕 |
| 热评 | `x/v2/reply?type=1&oid=<aid>&sort=2` | 取前 20 条高赞，喂给大模型判断口碑 |
| 排行 | `x/web-interface/ranking/v2` | 分区榜 |
| UP 投稿 | `x/space/wbi/arc/search` | 需要 WBI + 登录态，容易风控 |

**三个坑：**

1. **WBI 签名**：2023 年后搜索/空间接口都要签名，签名算法会变。别自己硬写，用现成库（`bilibili-API-collect` 社区有实现），或直接复用浏览器 Cookie + 用 Playwright 走页面。
2. **风控 412**：频率高 / IP 脏就封。控制 **1 请求/秒**、带真实 `buvid3`、失败退避重试。
3. **GitHub Actions 的 IP 大概率被风控**。所以：**采集在你本地跑**，跑完把 JSON 提交上来，Actions 只负责构建。别指望 CI 帮你爬。

> 合规：只存索引（标题、封面 URL、统计数、BV 号），不下载视频、不转码、不二次分发。站内播放走 B 站官方 iframe。

## 3. 评分：先杀负信号，再算分

### 3.1 负信号（命中 2 条直接丢，不看分数）

| 类别 | 判定 |
|---|---|
| 标题党 | 「震惊」「保姆级」「一篇搞定」「全网最全」「2025最新」「0 基础 3 天」「看完直接上岗」 |
| 营销号 | 简介含「加群 / 领资料 / 私信 / 课程 / 付费」；合集超过 30 集；同标题在多个平台出现 |
| 搬运 / 念稿 | 评论区高频出现「念稿」「AI 配音」「听不懂」「废话」「广告」「割韭菜」 |
| 时长异常 | 用 8 分钟讲完 Transformer、用 3 分钟讲完 RAG（除明确的「速览」定位） |
| 明显切片 | 时长 < 90 秒且无上下文；同一视频被切成 10 段分别发布 |

### 3.2 硬信号（可计算）

| 信号 | 怎么算 | 为什么 |
|---|---|---|
| 互动率 | `(点赞+投币+收藏) / 播放` | 核心指标。营销号通常 < 1.5%，优质内容 5%-10% |
| **收藏率** | `收藏 / 播放` | **最像「值得反复看」的指标**，比点赞更诚实 |
| 评论质量 | 高赞评论的语义（LLM 判） | 「讲得清楚」vs「求资料」「已买课」 |
| 弹幕密度 | `弹幕 / 分钟` | 过高可能是刷的，过低可能没人看 |
| 作者先验 | 该 UP 历史平均互动率 + 是否在信任名单 | 一次验证，长期受益 |
| 新鲜度 | 发布时间衰减（半年内权重高） | 技术类内容会过时 |

### 3.3 LLM 打分（0-100，五个维度）

把 `标题 + 简介 + 前 20 条高赞评论 + 时长 + UP` 喂给模型，让它按五个维度打分并给一句理由：

| 维度 | 在问什么 |
|---|---|
| 信息密度 | 有没有具体例子、数字、推导？还是全程正确的废话？ |
| 讲人话 | 术语有没有解释？是「深入浅出」还是「照本宣科」？ |
| 结构 | 有没有清晰的路线（先讲什么后讲什么）？ |
| 深度 | 与主题匹配的深度，不是越深越好 |
| 原创度 | 是原创讲解，还是念别人的稿 / 搬运 |

### 3.4 三个场景标签（modes）

每个视频最后还要打一个「适合在什么场景看」的标签，一个视频可以占多个：

| 标签 | 判定依据 | 例子 |
|---|---|---|
| `focus` 专注 | 需要看画面才能懂 | 代码演示、画图讲解、实操录屏 |
| `relax` 刷一刷 | 短（≤10 分钟）且信息密度够，可以随时打断 | 7 分钟的 Transformer 类比、5 分钟的公司八卦式复盘 |
| `listen` 只听 | 纯口播 / 访谈 / 复盘，**不依赖画面** | 31 分钟的 OpenAI 访谈、面试题讲解 |

`listen` 由大模型读简介 + 高赞评论判断：「这个不看画面能听懂吗」。
这条判断决定了「骑车时能不能听」——判错了，那一整个队列就废了。

### 3.5 总分

```
score = 0.35·LLM + 0.25·互动率 + 0.15·收藏率 + 0.15·作者先验 + 0.10·结构
        − 负信号扣分
```

| 分数 | 处理 |
|---|---|
| ≥ 80 | 直接入库 |
| 60-79 | 进人工终审队列（每天看 Top 20） |
| < 60 | 丢弃，但保留记录（避免重复采） |

**为什么 LLM 权重最高**：播放和互动可以被营销手段做大，但「它到底讲没讲清楚」只有读内容才知道。

## 4. 人工终审：每天 10 分钟

不是让你看视频，是让你看**卡片**：标题 + 封面 + 分数 + 一句 LLM 理由 + 3 条高赞评论。

- 「通过」→ 入库，选主题、切章节
- 「不要」→ 记录理由（太浅 / 太营销 / 讲得乱）→ **回流去调整权重**
- 「这个 UP 不错」→ 加入信任名单，后续他的新视频直接加权

> 这一步不能全自动。你的品味是这个网站唯一的护城河，AI 只负责把 500 条压到 20 条给你看。

---

## 5. 「越多越好」怎么成立：队列怎么补

内容多了不代表能一直刷。要给队列定规则：

```
队列 = 当前主题 ∩ 没看过 ∩ 没点「不感兴趣」
      → 按 (质量分 × 新鲜度 × 你的偏好) 排序
      → 滑到第 N 条时，从候选池补 20 条进来
```

- **不会重复**：看过 / 划过就下沉，30 天内不再出现。
- **不会跑题**：队列只在当前主题内，刷完提示换主题。
- **不会断**：候选池 < 20 条时，首页提示「本周新增不足，去跑一次采集」。

目标量：**起步 200-300 条**（够刷 8-12 小时），之后**每周 +30-50 条**。

## 6. 调度与成本

| 项 | 方案 |
|---|---|
| 频率 | 每周一次（周日晚上跑），新视频进候选池 |
| 运行位置 | **你本地**（`pnpm fetch`），跑完 `git push` |
| 耗时 | 500 条候选 ≈ 8-10 分钟（限速 1 req/s） |
| LLM 成本 | 500 条 × 约 800 tokens ≈ **1 元以内** |
| 人工 | 每天 10 分钟看 20 张卡 |
| 上线 | 合并 PR → Actions 构建 → 1 分钟后线上更新 |

## 7. 反馈闭环（让系统越用越准）

| 你的动作 | 系统学到什么 |
|---|---|
| 👍 喜欢 | 该作者 +、该标签 +、该场景 + |
| 👎 不感兴趣 | 该作者 −、该标签 −；**连续 3 次被踩的作者，新视频不再进候选池** |
| 只在「刷一刷」里刷 | 多采短视频 |
| 只在「只听」里用 | 多采口播型、访谈型 |
| 手动加一条 | 作为新的种子，扩散它的相关推荐 |

每两周重新算一次作者权重，信任名单会自己长大。

## 8. 落地顺序

| 步 | 做什么 | 产出 |
|---|---|---|
| 1 | 手工填 20 个种子 UP + 30 个关键词 | `seeds.json` |
| 2 | 写 `scripts/fetch.mjs`：种子 → related 两层 + 搜索 | 候选 JSON |
| 3 | 接 `view` / `reply` 接口，补齐统计与热评 | 完整候选 |
| 4 | 写评分脚本：硬信号 + 负信号 + LLM | 带分数的候选 |
| 5 | 终端/TUI 审卡（先不写 UI） | 入库 JSON |
| 6 | 入库的补章节（大模型给初稿，你校正） | videos.json |

**第 5 步先用命令行就够**，等真的要每天审 100 条再写网页版审核台。

## 9. 风险

| 风险 | 对策 |
|---|---|
| B 站接口签名/风控变化 | 采集层独立成一个脚本，坏了只影响采集，线上不受影响 |
| 站外（知乎）反爬 | 半自动：你贴链接，脚本抽 BV |
| 评分偏了，漏掉好视频 | 保留「被丢弃」记录，每周抽样看 10 条，发现漏杀就调权重 |
| 越采越杂 | 主题 + 章节 + 标签三层约束；每季度清一次低分老视频 |
| 版权 | 只索引不下载，页脚声明，播放走官方 iframe |
